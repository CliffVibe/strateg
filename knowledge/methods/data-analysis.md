# Анализ данных

## Перед расчётом — паспорт данных
Для каждого файла в `inputs/`: что за строка (пользователь, сессия, заказ), период, единицы, определения полей,
пропуски, дубликаты, выбросы, смены методики. Запиши в `work/calc/<имя>-passport.md`.

## Воспроизводимость
Расчёты — кодом (`work/calc/*.py`), не «в уме». Скрипт читает из `inputs/`, пишет результат и печатает
проверки. Результат расчёта → источник `--type calc` со ссылкой на скрипт → утверждение `fact` (о данных) или `forecast`.

## Проверки, которые всегда
- Сумма частей = целое; доли в пределах 0–100%.
- Периоды сопоставимы (неполный месяц, сезонность, праздники).
- Знаменатель метрики определён (удержание от кого: всех установивших? активировавшихся?).
- Изменение методики сбора / трекинга — частая причина «падения» метрики.
- Выживаемость когорт, а не средняя по всем — для удержания.

## Методы по задаче
| Вопрос | Метод |
|---|---|
| Падает удержание | когортный анализ, разложение по сегментам и каналам, проверка трекинга |
| Что влияет на конверсию | воронка по шагам, сравнение сегментов; корреляция ≠ причина |
| Размер рынка | top-down и bottom-up, сравнить; все допущения — `assumption` |
| Эффект изменения | до/после с контролем, разница разностей, A/B |
| Качественные данные | кодирование, частота тем, цитаты |
