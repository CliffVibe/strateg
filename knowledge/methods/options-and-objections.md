# Варианты и возражения

## Варианты должны быть содержательно разными
Не «A, A+, A++». Разные варианты отличаются **ставкой**: кого обслуживаем, какую работу, какой моделью, каким ресурсом.
Обязательно:
- **Оставить как есть** — с честной оценкой, что будет (это тоже прогноз).
- **Закрыть / свернуть направление** — с высвобождаемыми ресурсами и потерями.
- 1–3 активных варианта (например: сменить аудиторию; сменить модель монетизации; углубить ядро; партнёрство).

## Для каждого варианта
1. **Суть** в 2 строках.
2. **Что должно быть правдой**, чтобы он был лучшим (3–5 условий, со ссылками [C…]). Это главный инструмент сравнения.
3. **Эффект и затраты:** с пометкой факт/прогноз/допущение.
4. **Сильнейшие возражения** — от `red-team`: настоящие, которые сказал бы скептичный CFO, юрист, лидер клиентского сервиса,
   конкурент. Не соломенные чучела.
5. **Что теряем**, выбирая его.

## Pre-mortem
«Прошёл год, вариант провалился. Почему?» — 3–5 причин. Вероятные — в риски и guardrails плана проверки.

## Сравнение и рекомендация
Таблица по критериям из framing. Рекомендация агента + уверенность + **что изменит рекомендацию** (какой факт).
Выбирает человек (ворота choose).
