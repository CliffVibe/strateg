# T04. Маршрутизация: какая модель размечает тип утверждения

**Вопрос.** Нужен ли для проверки типа утверждения (fact / hypothesis / forecast / assumption) что-то сильнее
haiku — sonnet или внешний Jev?

**Ответ.** Нет. На 40 утверждениях T02 haiku-`verifier` размечает тип так же точно, как sonnet: 40 из 40 в каждом
из 8 прогонов. При этом он в 10–15 раз дешевле: $0,004–0,005 против $0,05–0,08 за 40 утверждений. Jev не проверяли:
ключа нет. Даже при идеальной точности он сэкономил бы меньше $0,01 на проверку. Правило ниже: haiku по умолчанию,
эскалация на sonnet только по узким признакам.

## Как мерили

- **Эталон:** `claim-kinds.jsonl` — 40 действующих утверждений проекта `antifraud-free`: все 4 допущения, все
  9 прогнозов, все 16 гипотез и 11 из 25 фактов. Черновой эталон разметил Claude по рубрике `claim-kinds.md`.
  Человек ещё не проверил его (см. «Что нужно от человека»). С типом в реестре эталон не совпадает в 2 строках из 40.
- **Задание** (`python eval/score.py prompt`): рубрика, ID скрыты (E01…E40), порядок перемешан. Модель отвечает
  JSON-строкой с типом и уверенностью 0–1. Инструменты не нужны: субагент читает один файл с заданием.
- **Два варианта задания:**
  - *base* — у каждой строки указаны источники (`S004:web`, `S018:calc`) и связи;
  - *hard* (`prompt --hard`) — только формулировка: без источников и ссылок `[C…]`, со снятыми метками
    «Прогноз Q05:», «Допущение…», «(red-team)». Так тип приходится определять по смыслу, как у фразы из
    черновика документа.
- **Модели:** субагент `verifier` с моделью по умолчанию (haiku) и с `model: sonnet`. Каждая модель — 2 прогона
  на каждый вариант задания.
- **Стоимость и время** — из транскриптов субагентов (`score.py record --transcript`), в ценах
  `config/pricing.json`. Время — от первой до последней записи транскрипта.

### Что видно

1. **Задача насыщена.** Обе модели не ошиблись ни разу: ни с подсказками, ни без. У этого набора правило «ноль
   ошибок из 40» даёт верхнюю границу доли ошибок haiku ≈ 7% (правило трёх, 3/40). Различить модели внутри этих 7%
   может только набор побольше и потруднее. Для разметки типа такая точность достаточна.
2. **Цена — в основном фиксированный контекст субагента, а не разметка.** Каждый вызов несёт ≈ 37 тыс. токенов:
   системный промпт, описание инструментов, задание. Большая часть идёт записью в кэш. Ответ — 1,3–4,4 тыс.
   токенов. Поэтому типы выгоднее проверять одной пачкой: 40 утверждений обходятся haiku в ≈ $0,0001 за штуку.
3. **haiku медленнее sonnet** — 15–18 с против 8–11 с. Он рассуждает перед ответом: выход 3,3–4,4 тыс. токенов
   против 1,3 тыс. у sonnet. Для проверки перед воротами разница в 7 секунд не важна.
4. **Уверенность модели почти не информативна.** Однозначные и граничные строки получают в среднем 0,86 и 0,84.
   Ниже 0,7 — 1–3 строки из 40, и все ответы верные. Откалибровать порог на этих данных нельзя: ошибок нет.
   Порог 0,7 взят как дешёвый: эскалируется 1–2 строки, это +$0,001–0,002. При пороге 0,8 эскалировалась бы
   четверть набора, при 0,9 — больше половины.
5. **Разметку реестра модели проверяют полезно.** Обе модели во всех прогонах назвали C025 и C072 фактами.
   В реестре T02 эти утверждения записаны гипотезами, хотя C046/C047 с той же «выдачей поиска» — фактами.
   Расхождение «модель ↔ реестр» — сигнал непоследовательности, и `verifier` его найдёт.

### Ограничения

- Один проект, 40 строк. Все формулировки написал сам агент, и он знал тип. Вариант *hard* снимает явные метки,
  но не стиль: «возможно», «значит», «≈» остаются в тексте.
- Эталон — черновик Claude. Человек его ещё не проверил.
- Проверялась только **разметка типа**. Главную работу `verifier` в T02 — найти формулировки сильнее
  снимка (11 случаев) — этот набор не мерит. Для неё правило прежнее (`verifier.md`): низкая уверенность или
  PDF без текста → повтор на сильной модели.
- Цены — из `config/pricing.json` на 31.10.2026, сторонние источники. Сверить с официальной страницей Anthropic.

## Jev (TypeSafe): что проверили

Читали официальную документацию, 11.11.2026: docs.typesafe.ai (`models`, `introduction/quickstart`,
`api/system-one`, `primitives/choice`, `api/errors`), typesafe.ai, `legal/terms` (19.09.2026),
`legal/acceptable-use-policy` (23.09.2026).

| Что | По документации |
|---|---|
| Запрос | `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer <ключ>`; тело `{"model", "state", "questions"}`. Вопрос «выбор»: `{"type": "choice", "instructions": "…", "criteria": {"fact": "описание", …}}` — от 1 до 255 вариантов |
| Ответ | `answers.<id>`: `choice`, `confidence` (0–1), `probabilities`; `usage.input_tokens` |
| Модели | `jev-1.14.0` (с 14.10.2026), `jev-1.13.0`; псевдонимы `jev-latest` и `jev-preview` указывают на 1.14.0. Документация советует закреплять версию, если пороги уверенности подобраны под неё |
| Цена | $0,042 за 1M входных токенов (1.13 и 1.14); выход бесплатен. Бесплатный уровень не найден |
| Лимиты | 64 тыс. токенов на запрос (262 тыс. с заголовком long-context), тело ≤ 32 МиБ; лимит частоты — по организации, число не опубликовано |
| Русский язык | Явно не заявлен: «reads natural-language text» |
| Доступ из РФ | Условия сайта (п. 13(g)): сайт «предназначен для посетителей в США», доступ оттуда, где он незаконен, запрещён. Явного списка стран нет. Условия API (Master Customer Agreement) не читали. Способ оплаты не указан |
| Инъекции | Отдельного раздела нет. `state` — просто содержимое, к которому относятся вопросы |

**Решение:** ключа `TYPESAFE_API_KEY` нет ни в окружении, ни в `.env`, поэтому шаг 2 пропущен: `scripts/jev.py`
не писали. Подключать Jev нет смысла и с ключом. haiku уже даёт 40/40 за ≈ $0,005, и экономия меньше $0,01 на
проверку не окупит внешнюю зависимость: условия только для США, русский язык не заявлен, данные проекта уходят
стороннему API. Вернуться к Jev стоит, если классификация станет массовой, например тысячи утверждений на проект.
Тогда сначала прочитать MCA, потом прогнать тот же эталон: `score.py record jev --answers … --model jev-1.14.0`.

В `config/pricing.json` (`external.jev-1.13`) источник цены — обзор. По официальной странице цена та же,
$0,042 за 1M, но актуальная версия — `jev-1.14.0`. `config/` вне рамок T04, поправить отдельно.

## Правило маршрутизации (патч AGENTS.md §5)

Патч — `eval/T04-agents-routing.patch`. Применяет человек: `AGENTS.md` защищён хуком.

- Тип утверждения проверяет `verifier` на haiku, **одним вызовом на все утверждения** этапа, а не по одному.
- Эскалация на sonnet (`verifier` с `model: sonnet`) — только по отдельным утверждениям:
  - haiku дал уверенность в типе < 0,7;
  - тип haiku расходится с реестром по линии «факт ↔ не-факт»: это меняет вес утверждения как доказательства;
  - сверку цитаты не сделать дёшево (PDF, изображение) или проверка ответила «Уверенность: низкая».
- Каждая эскалация — `strat log --kind routing "…"`: что, почему, чем кончилось.
- Jev не используется (см. выше).

Чтобы порог работал, `verifier` должен выдавать уверенность по каждому утверждению, а не одну на весь отчёт.
Строка про это — в том же патче (`.claude/agents/verifier.md`).

## Что нужно от человека

Проверить черновой эталон. Файл `eval/claim-kinds.jsonl`, 40 строк: поле `text` — формулировка, `gold` — тип по
эталону, `registry_kind` — тип в реестре. Достаточно просмотреть **11 строк** с `ambiguous: true`, в них входят
обе строки с `gold ≠ registry_kind`; остальные однозначны. Ключевые — **C025** и **C072**: эталон говорит «факт», реестр —
«гипотеза». Не согласны — впишите в строку `"human": "<тип>"` и `"human_note": "почему"`. Затем:
`python eval/score.py score`.
