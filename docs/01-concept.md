# 01. Концепция

## Для кого и зачем
Руководитель цифрового продукта каждый день решает вопросы вроде «почему падает удержание», «кому и как продавать», «что сказать
аудитории». Ответ требует исследования, данных, интервью и сравнения вариантов — на это нет времени. Обычный чат с ИИ даёт уверенный
текст без проверяемых оснований: непонятно, чему верить, а через неделю нельзя вспомнить, на чём держалось решение.

## Ставка
**Доверие, а не текст.** Агент строит рекомендацию на реестре утверждений: каждое помечено как факт, гипотеза, прогноз или
допущение и связано с источником. Отсюда растут все сильные стороны:
- проверяемость — клик от вывода к цитате и снимку источника;
- честность — пробелы видны, синтетика не выдаётся за спрос (это запрещено кодом, а не только инструкцией);
- пересмотр — новый факт → `impact` показывает затронутые выводы, документы и решения;
- поддержка после решения — решение помнит свои основания и сигналит, когда они устарели.

## Принципы
1. **Человек решает** — четыре ворот: постановка, план и бюджет, выбор варианта, принятие стратегии.
2. **Спрашивать только то, что меняет следующий шаг.**
3. **Исследовать только то, что может изменить решение** (ценность информации).
4. **Каждый компонент окупается**: 5 субагентов — каждый ради качества или цены; никаких MCP по умолчанию (встроенного поиска хватает).
5. **Всё в файлах** — состояние переживает новый чат, другую среду (Cursor), сбой.

## Соответствие требованиям
| Требование | Как закрыто |
|---|---|
| Поставить задачу | `/start`, `problem-framing.md`, `brief.md`, ворота intake |
| Собрать материалы со ссылками | `researcher`, `strat source add` (+ снимок, sha256), `inputs/` |
| Исследование от вопросов, пробелы | `plan.json` (вопросы с `why`), `situation.md` «Чего не знаем — и почему» |
| ≥ 3 варианта, «оставить как есть», возражения, факты ≠ гипотезы | `options.md`, `red-team`, `strat check` проверяет всё это |
| Продуктовая, коммуникационная, план проверки | шаблоны + методология + `strat check` по обязательным разделам |
| Workflow с человеком | 10 этапов, `strat stage`, ворота |
| Порядок в знаниях | 7 слоёв (AGENTS.md §2), раздельные папки, защита хуками |
| Продолжение после перерыва | `state.json`, `journal.md`, `next_action`, хук `session-start`, `/resume` |
| Прозрачность и стоимость | журнал, реестры, хук `stop` → `costs/`, `strat cost`, раздел отчёта «Как получен результат» |
